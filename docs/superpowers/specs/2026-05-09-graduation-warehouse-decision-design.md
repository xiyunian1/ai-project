# 毕业设计增强方案：WMS 智能仓储辅助决策系统

## 1. 课题定位

本项目以 `ai-project/` 为毕业设计主体，定位为“基于 Spring Boot 与 Vue 的 WMS 智能仓储辅助决策系统设计与实现”。系统面向仓储运营场景，把用户认证、库存查询、低库存预警、自然语言数据分析、流程指导和智能问答整合到同一工作台中。

外部平台仓库不作为毕业设计主体，也不作为当前运行依赖。答辩与演示重点集中在 `ai-project/ai-frontend` 和 `ai-project/my-ai`。

## 2. 设计目标

- 形成清晰的毕业设计主线：低库存/异常发现 -> 数据查询 -> AI 分析 -> 处理建议 -> 流程指导。
- 提升答辩第一印象：登录后进入系统概览页，让老师快速理解系统能力和业务价值。
- 保持实现风险可控：优先复用现有接口、页面和样式体系，不进行大规模架构重构。
- 提高现场演示可信度：使用真实 SQL Server 和真实模型配置；外部 AI 服务不可用时显示明确错误并检查配置。
- 补齐毕业设计材料：增加系统说明、接口说明、数据库说明和演示路径文档。

## 3. 推荐方案

采用“最小高收益答辩增强版”。该方案不新增复杂审批流或工单表，而是通过系统概览页、库存到分析的联动和文档补强，将现有功能串成完整业务闭环。

本轮不做以下事项：

- 不修改外部平台仓库。
- 不重构后端包结构。
- 不引入新的前端框架或 UI 库。
- 不新增复杂库存处置表、审批表或工单表。
- 不使用本地模拟回答替代真实模型；演示前应准备可用的模型配置。

## 4. 功能设计

### 4.1 系统概览页

新增 `/dashboard` 页面，作为登录后的默认首页。

页面内容包括：

- 系统名称与课题定位：WMS 智能仓储辅助决策系统。
- 核心能力卡片：库存预警、智能分析、流程指导、文档处理。
- 运行状态摘要：低库存预警数量、库存查询入口、分析入口、系统演示入口。
- 推荐演示流程：查看预警 -> 查询库存 -> 生成 AI 建议 -> 核对流程。

该页面主要服务毕业答辩和系统展示，不承载复杂业务逻辑。

### 4.2 导航调整

在共享侧边栏功能区加入“系统概览”。登录成功后从 `/chat` 改为跳转 `/dashboard`。

已有功能保持：

- `/chat`：智能问答工作区。
- `/analysis`：数据分析工作区。
- `/inventory`：库存洞察页。
- `/workflow`：流程助手页。
- `/document-process`：文档处理页。

### 4.3 库存到分析联动

在低库存预警卡片中增加“生成建议”按钮。点击后跳转到 `/analysis`，并通过 URL query 传递待分析问题。

问题模板示例：

```text
请根据商品“{productName}”当前库存 {currentStock}，分析低库存风险，并给出补货、供应商沟通和流程处理建议。
```

该设计复用现有分析页能力，不新增后端接口。

### 4.4 分析页接收预置问题

`Analysis.vue` 读取 URL query 中的 `query` 参数。若当前分析会话为空，则将该问题填入输入框，方便用户直接发送；若页面已有会话，则只作为输入框预置内容，不自动覆盖历史消息。

本轮默认不自动发送，避免页面跳转后触发不可控外部 AI 请求。答辩演示时由用户点击发送，行为更可控。

### 4.5 文档材料补强

新增面向毕业设计的文档：

- `docs/graduation-design.md`：课题定位、系统功能、技术架构、演示流程。
- `docs/api.md`：主要接口说明。
- `docs/database.md`：核心数据表与字段说明。

这些文档用于论文编写、答辩准备和项目交付说明。

## 5. 数据流设计

核心演示数据流：

1. 用户登录，前端保存 JWT。
2. 前端进入 `/dashboard`，展示系统入口与摘要。
3. 用户进入 `/inventory`，前端调用 `/api/tools/low_stock` 获取低库存数据。
4. 用户点击某条预警的“生成建议”。
5. 前端跳转 `/analysis?query=...`。
6. 分析页读取 query，填入分析问题。
7. 用户点击发送，前端调用 `/api/ai/chat/analyze/stream`。
8. 后端通过 `SqlAnalysisService` 调用真实模型规划 SQL、执行只读查询并返回分析结果。
9. 用户可切换 `/workflow` 查看入库、出库和异常处理流程。

## 6. 错误处理与演示稳定性

- 未登录访问受保护页面时，继续使用路由守卫跳回 `/login`。
- 库存接口失败时，页面显示已有错误提示，不阻断其他功能入口。
- 分析页不自动发送 query，避免一进入页面就因外部服务失败影响演示。
- 聊天服务使用真实模型调用；外部 AI 服务不可用时返回明确错误并提示检查模型配置。
- SQL 分析保留只读查询、表白名单和 SQL 修复保护，避免演示时执行危险 SQL。
- 文档处理作为扩展模块展示，若本机未安装 Codex CLI，应在文档中说明依赖和替代演示方式。

## 7. 测试与验证

本轮改动完成后至少执行：

- 前端：在 `ai-project/ai-frontend` 执行 `npm run build`。
- 后端：若只改前端和文档，可不跑全量后端测试；若后端接口发生变化，则在 `ai-project/my-ai` 执行相关 Maven 测试。

建议补充或整理的验收用例：

- 登录成功后进入系统概览页。
- 未登录访问 `/dashboard` 会跳转登录页。
- 侧边栏可以在概览、库存、分析、流程、文档之间切换。
- 库存页低库存数据可正常展示。
- 点击低库存“生成建议”后，分析页输入框出现预置问题。
- 前端生产构建成功。

## 8. 预期答辩演示脚本

1. 打开登录页，说明系统面向 WMS 仓储运营场景。
2. 登录后进入系统概览页，介绍课题主线和核心模块。
3. 进入库存洞察页，展示低库存预警和商品查询。
4. 选择低库存商品，点击生成处理建议。
5. 在分析助手中展示预置问题，发送后查看分析结论和 SQL 明细。
6. 切换到流程助手，说明处理建议如何对应入库、出库和异常流程。
7. 可选展示智能问答或文档处理，作为系统扩展能力。

## 9. 成功标准

- 项目主线从“AI 功能集合”调整为“仓储智能辅助决策系统”。
- 登录后有清晰的系统入口和毕业设计展示页。
- 库存预警与 AI 分析形成可演示闭环。
- 文档能够支撑论文中的需求分析、系统设计、接口设计、数据库设计和测试说明。
- 前端构建通过，现有功能不被破坏。
